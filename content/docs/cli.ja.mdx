## 何のためにあるのか

サーバー、SSH セッション、自動化されたジョブ。これは、画面ではなくテキスト インターフェイスを備えたアプリと同じ拡張エンジンであるため、グラフィカル セッションは必要ありません。

## 方向性を知る

まず help コマンドを実行し、次に Doctor コマンドを実行して、ランタイムがロードできることを確認し、ジョブを信頼する前に必要なものすべてに到達できることを確認します。

## 拡張機能の操作

リポジトリが提供するものをリストし、それを検証し、ライブ サイトに対してソースをテストします。テストは、単純なソースのロードから検索と詳細呼び出しの実行まで、段階的に実行されます。

## ソースを直接呼び出す

検索などの単一の操作を呼び出して、JSON を取得できます。これが、コマンド ラインがスクリプト作成やソースのデバッグに役立つ理由です。

## ネットワーク経由でサービスを提供する

アプリが公開するのと同じ Web サーバーを起動できます。これが、リモート クライアントがヘッドレス マシンと通信する方法です。

## まだやっていないこと

コマンド ラインはアプリのローカル データベースを開かないため、ライブラリ、履歴、ダウンロード キューのコマンドはヘッドレスでは使用できません。それらの人にはまだアプリが必要です。

## 早見表

- コマンドラインはアプリの拡張エンジンを再利用します。
- Doctor コマンドは、ランタイムに依存する前にランタイムをチェックします。
- ソースは、読み込みから検索まで段階的にテストできます。
- ライブラリとダウンロードのコマンドには引き続きアプリが必要です。

## 契約 / 例

```bash
watchtower --cli help
watchtower --cli doctor --json
watchtower --cli extensions list --repo ./my-repo
watchtower --cli extensions test --repo ./my-repo --mode smoke
watchtower --cli source 1900000002 search --query "space opera" --json
```
