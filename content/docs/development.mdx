# Development

Watchtower has two active codebases. Work in the repository that owns the behavior you are changing.

## Flutter application

The `watchtower` repository contains the mobile application, normalized models, services, and generic renderers.

```bash
flutter pub get
flutter analyze
flutter test
```

When working on the home screen, verify both a source with a custom layout and a source that relies on defaults. Pay special attention to loading, empty, and failed image states.

## Extensions

The `watchtower-extensions` repository contains source modules and JSON layout declarations.

```bash
npm install
npm run validate
```

The extension validator is the quickest feedback loop for syntax, JSON, and index consistency.

## A focused change

1. Add or update source behavior in `watchtower-extensions`.
2. Add the layout declaration there if the source needs a different composition.
3. Update the generic renderer in `watchtower` only when the presentation is reusable.
4. Run the extension validator.
5. Run Dart analysis and tests in an environment with Flutter installed.
6. Review the complete user path, not only the data response.

## Review checklist

- Does the feature work when the list is empty?
- Are source-specific rules kept out of generic widgets?
- Is the JSON still the source of truth for section presentation?
- Are URLs and external links safe and expected?
- Does the change preserve existing sources that have no layout declaration?
