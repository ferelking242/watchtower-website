## How to read the catalog

The code panel groups all 199 GalleryComponentCatalog ids by their current source category. These stable kebab-case ids are what go in layout JSON. The ids and descriptions live in watchtower/lib/models/gallery_component_catalog.dart; the home renderer and legacy section definitions live in watchtower/lib/models/layout_component_registry.dart.

## Home section renderers

For home.sections[].component, the registered base renderers are spotlight (alias carousel), banner, hero, ranked, newHot (alias new_hot), rankedWide, showcase, creatorRow, landscapeStacked, backdropWide, studioExplorer, universeExplorer, collectionTimeline, grid, catalogue, discoverGrid, category, categoryPills, doubleFeature, editorialSplit, masonry, feed, collectionCards and playlistCarousel. Compatibility ids compactRow (alias compact), historyRow, metadataPoster and statusPoster remain accepted but are not new picker choices.

## Specialized card slots

A home grid can select the mangaFeaturedCard or mangaChapterCard for manga items; homeEpisodeCard is the episode-card option; chapterCard belongs to chapter context. These are not interchangeable with the home section component. Context support is checked separately.

## Common properties

A section may set title, icon, accent, seeAll, paginated, requiresAuth and monthSelector. Grid sections additionally use columns, rows, cardStyle, gridOrder and scrollDirection. Gallery-backed ids can read their family-specific values from params; only use keys supported by that component family.

## The 199 gallery ids

The complete list is grouped by the catalog's own categories in the code panel. It includes rich media, discovery, rankings, collections, watch cards, manga and reading cards, streaming/progress cards, episodes and reusable sections. The source catalog carries each id's label, category, description, renderer family and selectable state.

## Compatibility and picker state

An id marked selectable: false still resolves so existing layouts can keep rendering, but the visual picker will not recommend it for a new layout. Do not delete compatibility ids or repurpose an id whose meaning is already stored in user JSON.

## Use only registered names

LayoutRegistry validates every home component against LayoutComponentRegistry. A typo or a component copied from a web mockup is an error, not a graceful no-op. Run the extension validator and confirm the id in the core registry before publishing.

## Kısa özet

- The catalog currently contains 199 stable gallery component ids.
- Home section renderers and specialized card slots are different contexts.
- Compatibility-only ids remain valid but are not offered for new selection.
- Unknown home component ids fail layout validation.
