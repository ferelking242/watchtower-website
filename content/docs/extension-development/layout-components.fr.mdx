## Lire le catalogue

Le bloc de code regroupe les 199 ids GalleryComponentCatalog par catégorie actuelle. Ces ids stables en kebab-case sont ceux à utiliser dans le JSON. Les ids et descriptions sont dans watchtower/lib/models/gallery_component_catalog.dart ; les moteurs de section et définitions historiques sont dans watchtower/lib/models/layout_component_registry.dart.

## Moteurs de sections d'accueil

Pour home.sections[].component, les moteurs enregistrés sont spotlight (alias carousel), banner, hero, ranked, newHot (alias new_hot), rankedWide, showcase, creatorRow, landscapeStacked, backdropWide, studioExplorer, universeExplorer, collectionTimeline, grid, catalogue, discoverGrid, category, categoryPills, doubleFeature, editorialSplit, masonry, feed, collectionCards et playlistCarousel. Les ids de compatibilité compactRow (alias compact), historyRow, metadataPoster et statusPoster restent acceptés, mais ne sont pas proposés pour les nouvelles mises en page.

## Emplacements de cartes spécialisés

Une grille d'accueil manga peut choisir mangaFeaturedCard ou mangaChapterCard ; homeEpisodeCard est prévu pour les épisodes et chapterCard pour le contexte chapitre. Ces cartes ne remplacent pas le composant de section d'accueil. Les contextes sont validés séparément.

## Propriétés courantes

Une section peut définir title, icon, accent, seeAll, paginated, requiresAuth et monthSelector. Les grilles utilisent aussi columns, rows, cardStyle, gridOrder et scrollDirection. Les ids du catalogue utilisent params pour leurs propriétés propres ; n'ajoutez que les clés prises en charge par la famille du composant.

## Les 199 ids du catalogue

La liste complète est regroupée par catégories dans le bloc de code : médias riches, découverte, classements, collections, cartes de visionnage, manga et lecture, progression vidéo, épisodes et sections réutilisables. Le catalogue associe à chaque id son libellé, sa catégorie, sa description, sa famille de rendu et son état de sélection.

## Compatibilité et sélection

Un id avec selectable: false reste reconnu afin de préserver les anciens JSON, mais le sélecteur visuel ne le recommande pas pour une nouvelle mise en page. Ne supprimez pas ces ids et ne réutilisez pas un id déjà présent dans les données utilisateur.

## Utiliser uniquement les noms enregistrés

LayoutRegistry valide chaque composant d'accueil à l'aide de LayoutComponentRegistry. Une faute de frappe ou un nom copié d'une maquette web est une erreur, pas un bloc ignoré. Lancez le validateur et vérifiez le registre avant publication.

## Mémo

- Le catalogue contient actuellement 199 ids de composants galerie stables.
- Les moteurs de section et les cartes spécialisées utilisent des contextes distincts.
- Les ids de compatibilité restent valides mais ne sont pas proposés aux nouveaux choix.
- Un composant d'accueil inconnu fait échouer la validation.
