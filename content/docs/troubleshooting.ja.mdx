## まずは絞り込むことから始めましょう

設定に触れる前に、問題の原因がネットワークなのか、それともデバイスなのかを判断してください。 1 つのソースに障害が発生し、他のソースはそのソースをポイントして動作します。失敗の原因はすべてアプリまたは接続にあります。

## 最初にすべてを更新します

リポジトリを更新し、拡張機能の更新をインストールしてから、アプリの更新を確認します。突然の破損の大部分は、変更された Web サイトと、すでに修正されているがまだインストールされていない拡張機能です。

## ソースが動作を停止しました

これは最も一般的な問題であり、通常は最も深刻ではありません。 Web サイトが変更され、拡張機能の更新が必要になり、リポジトリを更新することで修正されます。更新がまだ存在しない場合は、拡張機能の作成者が追いついていません。

## 何も読み込まれない

すべてのソースに障害が発生した場合は、代わりにネットワークに注目してください。設定でモバイルデータ、別の Wi-Fi ネットワーク、暗号化された DNS を試してください。単一のネットワークがすべてをブロックしていること、またはサインインしていないキャプティブ ポータルが原因となることがよくあります。

## サイトを開いてチェックに合格する

一部のサイトでは、回答する前に確認を行っています。 [参照] からソースを開き、内蔵ブラウザを使用してサイト独自のページを読み込み、手動でチェックを完了してから、ブラウザを閉じてアプリに戻ります。これを一度実行すると、多くの場合、そのソースのブロックがクリアされます。

## Cloudflareと無限のリロード

Cloudflareの背後にあるサイトは、ユーザーを通過させずにチェックをリロードし続ける可能性があります。内蔵ブラウザでサイトを再度開くか、詳細設定でユーザー エージェントを変更するか、サイトの保護が低下するのを待ってください。一部のソースは、アプリからの使用が意図的に困難になっています。

## Cookie と Web データのクリア

これにより、ログインを含むアプリの保存された閲覧状態がリセットされます。これはスタックしているチェックを正しく修正するものであり、ソースが停止していると判断する前に実行する価値があります。ソースにアカウントが必要な場合は、後で再度サインインする必要があります。

## ユーザーエージェントを変更する

ユーザー エージェントは、Web サイトに対してデバイスを識別する文字列であり、一部のサイトではこれをボット信号として扱います。デフォルトを一般的なブラウザ文字列に置き換えてからアプリを再起動すると、ループするチェックを通過できることがあります。

## 拡張機能がインストールされない

Android はデフォルトでストア外からのインストールをブロックします。ファイルマネージャーまたはブラウザーでこれを許可し、そのオプションがない場合は、代替ルートとしてShizukuを使用してください。ダウンロードが途中で停止した場合は別のメッセージが表示されるため、最初から再インストールしてください。

## コンテンツが間違った場所で開かれる

マンガがビデオ プレーヤーで開かれるか、エピソードがリーダーで開かれると、拡張機能は間違ったコンテンツ タイプを宣言します。これは設定ではなく拡張機能に問題があるため、ローカルで修正しようとするのではなく報告してください。

## クラッシュログと詳細情報の取得

詳細設定ではクラッシュ ログをダンプでき、デバイスからの logcat キャプチャによりアプリの動作がより詳細に表示されます。どちらも、曖昧な説明を追跡可能なものに変えるため、問題を報告するときに添付する価値があります。

## ストレージと読み取りの遅さまたは遅れ

読み込みが遅いのは通常、アプリではなくサイト、接続、またはレート制限が原因です。章内の画像が大きすぎると、読書の遅れが生じます。実際的な解決策は、ソースを切り替える、メモリを解放する、またはレート制限が過ぎるのを待つことです。

## あなただけではないとき

他の人も同じ失敗を経験した場合、それはあなたの設定ではなく拡張機能またはアプリに問題があります。新しいレポートを開く前に、プロジェクトの問題トラッカーでソースを確認し、アプリのバージョンと正確なエラー テキストを含めてください。

## 早見表

- 1 つの壊れたソースは、ほとんどの場合、アプリではなくソースです。
- 突然の破損の最も一般的な原因は、エクステンションの劣化です。
- すべてのソースに障害が発生した場合は、アプリの前にネットワークを疑ってください。
- 内蔵ブラウザでサイトを開くと、多くの検証チェックがクリアされます。
- Cookie と Web データをクリアすると、スタックしたチェックとログインがリセットされます。
- クラッシュ ログと logcat により、バグ レポートが追跡可能になります。

```text
# Narrow it down before changing anything
Does the site load in a browser?     if no, it is the source
Does another source work right now?  if yes, it is one source
Does the app work on mobile data?    if yes, it is your network

Then:  update the extension → open the site in the built-in browser
       → clear cookies and web data → check permissions
```
