# Architecture

Watchtower is split into a host application and a source repository. The host is deliberately opinionated about interaction and deliberately flexible about content.

## The runtime path

1. The extension index advertises a source and its capabilities.
2. The JavaScript runtime loads the extension and exposes its source functions.
3. Services such as `getCustomList`, `getPopular`, `getLatestUpdates`, and `search` normalize results into manga models.
4. `UiLayout` reads the source's JSON layout declaration.
5. `WatchHomeScreen` maps each section to a generic renderer.
6. The Flutter widgets render the same data with source-aware cards, navigation, and state handling.

```text
extension index
      ↓
JavaScript source runtime
      ↓
normalized content + layout metadata
      ↓
Flutter providers and services
      ↓
declarative home renderer
```

## The important boundary

An extension must not draw Flutter widgets or rely on private screen implementation details. It describes:

- what content exists;
- how a user can filter or search it;
- which sections should appear;
- the presentation hints for those sections.

The app decides how loading, errors, accessibility, navigation, theming, and caching work.

## Data shape

Sections carry a stable identity, title, list identifier, content items, and optional presentation hints. The bridge preserves `component`, `columns`, and `cardStyle` when it converts the JSON model into the legacy map consumed by the home screen.
