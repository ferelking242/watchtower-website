## Wofür es ist

Server, SSH-Sitzungen und automatisierte Jobs. Es handelt sich um die gleiche Erweiterungs-Engine wie die App mit einer Textoberfläche anstelle von Bildschirmen, sodass keine grafische Sitzung erforderlich ist.

## Sich orientieren

Beginnen Sie mit dem Befehl „help“ und führen Sie dann den Befehl „doctor“ aus, um sicherzustellen, dass die Laufzeitumgebung alles laden und erreichen kann, was sie benötigt, bevor Sie ihr einen Auftrag anvertrauen.

## Arbeiten mit Erweiterungen

Listen Sie auf, was ein Repository bietet, validieren Sie es und testen Sie eine Quelle anhand der Live-Site. Der Test läuft stufenweise ab, vom einfachen Laden der Quelle bis zum Durchführen der Such- und Detailaufrufe.

## Direktes Aufrufen einer Quelle

Sie können einen einzelnen Vorgang aufrufen, beispielsweise eine Suche, und JSON zurückerhalten. Das macht die Befehlszeile für die Skripterstellung und das Debuggen einer Quelle nützlich.

## Bereitstellung über das Netzwerk

Es kann denselben Webserver starten, den die App bereitstellt. Auf diese Weise kommuniziert ein Remote-Client mit einem Headless-Computer.

## Was es noch nicht tut

Bibliotheks-, Verlaufs- und Download-Warteschlangenbefehle sind nicht kopflos verfügbar, da die Befehlszeile die lokalen Datenbanken der App nicht öffnet. Die brauchen noch die App.

## Kurzüberblick

- Die Befehlszeile verwendet die Erweiterungs-Engine der App wieder.
- Der Doctor-Befehl überprüft die Laufzeit, bevor Sie sich darauf verlassen.
- Eine Quelle kann stufenweise getestet werden, vom Laden bis zur Suche.
- Für Bibliotheks- und Downloadbefehle ist weiterhin die App erforderlich.

## Vertrag / Beispiel

```bash
watchtower --cli help
watchtower --cli doctor --json
watchtower --cli extensions list --repo ./my-repo
watchtower --cli extensions test --repo ./my-repo --mode smoke
watchtower --cli source 1900000002 search --query "space opera" --json
```
